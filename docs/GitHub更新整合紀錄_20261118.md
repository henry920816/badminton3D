# GitHub 11/07 新功能整合紀錄

## 程式來源

- 底本：`badminton3D_原始格式輸出_完整專案_20261103.zip`，已包含 11/03 的品質檢查、批次修正、修正歷史、Update/Export Dataset 與原始格式保留。
- GitHub 對照分支：`henry920816/badminton3D` 的 `refactor/perf-and-cleanup`，核對提交 `2507de198d79a5b580f6f9ddcc2e4c7b899096d9`（2026-11-07）。
- 以 11/03 程式碼保留既有功能為優先，沒有整包覆蓋 GitHub 的舊版 2D 修正實作。

## 這次實際移植及整合的功能

1. **3D 場景比分**：`matchScore.js`、`Scene3D.jsx`。依 Rally 已結束的影格更新兩隊比分及已贏局數；沒有比分資料不顯示。
2. **Timeline 標註一致性**：新增跨相機 2D 視線的重投影 RMS 曲線，三台以上有效視角才計算；固定 1–1000 px 對數軸，避免縮放影響比較。
3. **Timeline 移除異常軌道**：取消最下方異常 Lane，保留 Rally、Hit、X/Y/Z、距離、速度及標註一致性。
4. **2D 修正極線參考**：在影片的 2D 修正或 2D 修復模式可開啟極線與多視角幾何交會點；**僅供人工定位，不會重新偵測或自動覆蓋標註**。
5. **統一鏡頭反投影**：新增 `imagePointToRay`，包含反畸變、外參反矩陣與回投誤差驗證。
6. **後端座標查詢**：新增 `GET /matches/{match_id}/traj2d/labels`，回傳可見 2D 的 frame/camera/x/y；原有 `/visible` 回傳格式不變。
7. **影片繪圖模組化**：將 2D 疊圖與影像點定位抽至 `utils/drawProjectionOverlay.js`，降低 `VideoPanel.jsx` 複雜度。
8. **移除拍頂／手掌疊圖按鈕**：配合 GitHub 介面精簡；保留 2D、3D 球點及人工修正疊圖。
9. **保留 11/03 功能**：紅色、藍色所有 Rally 一鍵修正、紫色人工檢視、修正上一步／下一步、Update Dataset、選擇性 Export Dataset（原格式）。

## 尚未聲稱完成的 GitHub 改動

此 ZIP 是 **11/03 底本的功能性整合版本**，不是 GitHub `refactor/perf-and-cleanup` 分支每個檔案的完全移植。GitHub 分支另有純 2D 物理軌跡合併/缺口模擬、完整影片時鐘 hook、2D 修正 hook、`main.py` 路由拆分、Dataset UI card 拆分、材質球拍 GLB 等變更；這些沒有直接覆蓋進來。若需要 GitHub 分支與本 ZIP 做完全等價的 Git 層級 merge，必須另外進行衝突消解與真實影片回歸，不能把本次通過語法/單元測試誤認為該工作已完成。

## 功能規則保持

- 3D 投影不在畫面、或沒有有效投影且存在 2D 時，依現有品質規則標藍；保留既有 50px 排除條件。
- 其他至少兩視角支持原始 3D、非擊球保護區且偏差大於 50px，依原規則產生紅色位置候選。
- 藍色／紅色一次處理目前資料集所有 Rally 的既有功能沒有被這次移植改寫。
- 所有 2D 修正仍寫入獨立修正資料層，不直接修改原始 2D。

## 執行

在根目錄啟動 Docker Desktop 後：

```powershell
docker compose up -d --build
cd frontend
npm ci
npm run dev
```

查看品質檢查的實際結果時，請選擇「修正後 2D」資料來源。重新整理不會刪除 PostgreSQL 資料。**不要執行 `docker compose down -v`**，以免刪除資料庫 Volume。

## 驗證範圍

- Python 後端使用 SQLite 測試替身跑單元測試，不代表 PostgreSQL 已實際啟動。
- Node 內建前端測試、TypeScript JSX 解析、相對匯入路徑及 ZIP 完整性可在離線環境檢查。
- 未在這個環境完成 Vite 正式打包、瀏覽器操作與實際多視角影片播放回歸；使用時應先確認 UI、攝影機排序、紅藍批次修正及匯入／匯出。
