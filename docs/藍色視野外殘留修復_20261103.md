# 藍色修正後仍殘留 — 修正說明

基於 2026-11-03「精簡品質檢查介面」完整專案的更新包；套用於同一版本，無須重新匯入資料集。

## 真正原因

舊版對「3D 明確在視野外、2D 卻有標註」全部塗藍，但只有同時具備兩台其他相機支持、離邊界大於 50 px、不在擊球附近、而且沒有先前修正的格子，才准許寫入修正層。因此按「藍色修正」時只處理一小部分；其餘藍色會一直存在。另一個顯示問題是「區段總覽」用整段的主要顏色填滿區段，中間正常的影格也可能看似藍色。若選到「原始 2D」來源，修正資料不會顯示，這是原始資料保持不變的正常現象。

## 這次做了什麼

1. 藍色 `outside_view` **只表示可以批次設為不可見**：原始 3D 明確投影在視野外超過 50 px、非擊球前後 5 幀、沒有既有修正。
2. **視野外的藍色不再要求其他兩台相機支持**：按使用者資料特性，原始 3D 整體可信且視野外衝突優先處理。紅色位置修正仍然要求其他兩台相機支持。
3. 離邊界小於等於 50 px、擊球保護區、已經有人工／先前修正的視野外疑點改列**紫色須人工檢視**，沒有隱藏或假裝已修正。這些格子保留 `review_issue_kind=outside_view`，讓使用者能看原因。
4. 全覽不再把多個不連續的錯誤用單一藍色長條蓋過正常影格；藍色只顯示真正藍色的 frame。
5. 批次修正後重新查詢 corrected 品質格，顯示剩餘藍色數及需人工檢視的視野外點數；若切回 original 2D，提醒切換到修正後查看。

## 安裝

在包含 `frontend/`、`backend/` 的專案根目錄執行：

```powershell
powershell -ExecutionPolicy Bypass -File "<更新包解壓縮位置>\apply_update.ps1"
docker compose up -d --build backend
cd frontend
npm run dev
```

重新開啟網頁，確認目前來源為「修正後 2D」。按「🔵 視野外修正」會先預覽與詢問確認。完成後，已修正的藍色會從 corrected 檢查結果消失；保護區內、不確定的視野外點會以紫色保留等待人工，而不是被偷偷刪掉。

**注意**：這次基於「原始 3D 整體可信」放寬藍色處理條件，少量相機校正錯誤的資料有誤隱藏風險。請先在單個 Rally 預覽並檢查，確定後再擴大使用。
