# 2D 檔案操作（2026-11-03）

這版只動 2D 檔案處理，Timeline、紅／紫／黃色判斷和原本的單點人工修正都保留。

## 全部 Rally 藍色一鍵消除

在「品質檢查」按 **🔵 全部 Rally 藍色一鍵消除**，後端掃描**目前資料集**全部 Rally、所有相機。即使正在看 Rally 1，也會處理 Rally 2、3……；不會改到其他資料集。

判斷仍沿用原本藍色規則：有可見 2D，但沒有可用的 3D 投影；或投影在畫面外，且 2D 與投影距離至少 50 px。這包含「3D 缺資料」的影格，所以一鍵消除前應先了解資料是否完整。

符合規則的點寫入 `ball_position_2d_corrections`，以 `visibility=0` 遮蔽；`ball_positions_2d` 原始資料不動。不跳確認視窗。全部 Rally 的修改屬於**同一次上一步**，可使用上方的「上一步／下一步」整批復原或重做。後端分段讀取資料，避免一次取出全場所有 3D／2D 資料。

## 輸出已修正的 2D

從上方 **2D 檔案 → 匯出修正 2D（ZIP）** 下載。

ZIP 包含每個 Rally／Cam 的 `*_ball.csv`（已套用目前修正層），另外附 `corrections.csv` 保留修正前後紀錄。檔案路徑為 `rallyN/viewC/v3/matchM_N_START_END_viewC_ball.csv`。匯出的 `matchM` 預設是目前資料庫 ID，不一定與最早匯入檔的 match 編號相同；Rally、Frame、相機欄位依資料庫記錄重新產生。

## 既有資料集：重傳部分 2D CSV

上方 **2D 檔案 → 部分重傳原始 2D**，可以一次選很多個 CSV。支援 `_calib_ball.csv`，並依檔名對應已存在的 Rally／視角／起訖 Frame。

- 不需要重傳整場。只替換被選到的 Rally／Cam 原始 2D 標註，其他檔案、Rally、3D、影片、相機參數不動。
- **整個指定 Rally／Cam 的 CSV 會被替換**，新檔缺少的 Frame 也會從該段原始 2D 中移除，不是只覆寫提供的幾列。
- 每次上傳先驗證全部檔名、範圍和 CSV 格式；有一個檔案不合規，整批都不寫入。
- 上限 300 個 CSV、單檔 24 MB、單批 256 MB。
- **既有 2D 修正層仍保留。** 因此看「修正後」時，該位置仍以舊修正為準；切到「原始」才能看到重傳後的底層點。這是避免重傳檔案時意外刪掉人工成果。
- 此處替換的是原始標註，**不屬於 2D「上一步」可復原的內容**。重傳前建議先匯出 ZIP 備份。

## 新增資料集：分次補傳、多選檔案

「新增資料集」的每一個類別現在都有 **多選檔案／補傳**：選多個檔案一次加入同一個上傳工作階段。已上傳的同一份檔案可以單獨重傳，其他已上傳類別不用清空。單次大量檔案會自動分批送到後端。

RallySeg.csv 與 shot_annotated.csv 可能在不同 Set 裡有相同檔名；這一類應繼續使用「選擇 Rally 資料夾」，保留資料夾路徑，避免兩份檔案混在一起。2D 羽球 CSV 若單選／多選沒有資料夾路徑，會依檔名自動補出 `rallyN/viewC/v3/`。

## 更新後啟動

在專案根目錄：

```powershell
# 先確認 Docker Desktop 已啟動
docker compose up -d db
docker compose up -d --build backend
cd frontend
npm ci
npm run dev
```

這裡的測試是 Python 模擬資料與前端模組邏輯測試；並未在真實影片、Windows 瀏覽器及 PostgreSQL 實測。匯出 ZIP、既有資料集重傳及跨全部 Rally 的清除都應先用一份可回復的測試資料確認。
