# 2D 品質檢查：相機列對齊、雙擊／長按、上一步／下一步

此更新包**以 2026-11-03「藍色人工檢視_點擊長按」完整版為底**。不修改原始 2D／3D 資料、紅色 >50 px 品質門檻或其餘頁面流程。

## 修改重點

- 品質格每列強制顯示 `Cam {camera.index}`，不再使用可能誤導的舊 label。色塊與命中格都使用同一個依相機真實 index 排序的清單；滑鼠座標根據畫面實際 `getBoundingClientRect()` 映射，修正縮小品質檢查區域時相機列與點擊位置偏移。點到某一列會切到對應相機及影格。
- 藍色 **單擊**：只定位相機、影格，不刪除。
- 藍色 **雙擊**：直接在修正層將該視角該影格標註設為 `visibility=0`。
- 藍色 **長按約 0.6 秒**：同視角向前後找真正連續的藍色，整段設為不可見；拖動超過 7 px 取消長按。雙擊和長按**都不跳確認視窗**。
- 新增頂部常駐 **「↶ 上一步」「↷ 下一步」**：手動 2D 位置更改、將標註設為不可見、清除修正、藍色整段移除、紅色批次及原有 2D 自動修復共用修正歷史。每批修改當成一步；按上一步後能再次按下一步。新修正會取消剩餘的下一步。
- 上一步／下一步及批次處理會清除失效的 2D 快取，重新讀取品質檢查與影片資料；後端對目前修正值做比對，若存在其他變更則不會直接覆蓋。
- 仍只更動 `ball_position_2d_corrections` 修正層，原始 `ball_positions_2d` 不變。

## 安裝

只需在**舊版專案根目錄**執行更新包的腳本。請先備份原專案，並保留原本的 PostgreSQL Volume。

1. 解壓縮更新包到任意位置。
2. 在 Windows PowerShell 進入**原本專案**（裡面有 `frontend`、`backend`、`docker-compose.yml`），執行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File "<解壓縮更新包的完整路徑>\apply_update.ps1"
   docker compose up -d --build backend
   ```

3. 前端若已有 `npm run dev`，通常 Vite 會熱更新；不確定時重新啟動前端並按 `Ctrl + Shift + R`。
4. 在右上角選「2D：修正後」以顯示刪除結果；切回「原始」仍看得到原始資料。

**無須刪除資料庫或重新匯入資料集**，因為本次重用已存在的修正紀錄表，沒有新增資料表。

## 使用注意

- 上一步／下一步僅涵蓋**套用本版後執行的新修正**；之前版本缺少完整前後狀態的舊歷史紀錄無法自動轉換。
- 頂部歷史按鈕對**目前資料集**操作，不因切換 Timeline／品質檢查或切換相機而丟失。
- 藍色只表示該相機原始 3D 投影在畫面外而 2D 有標註；雙擊或長按是使用者主動移除，系統不會自動刪除。
- 現有紅色**批次**仍保留原本的套用前預覽確認；使用者指定不需要的**藍色**確認視窗沒有加入。
- 當前沒有在你的真實 Windows、影片與 PostgreSQL 環境做過端對端點擊驗證。相機列對齊目前完成的是程式座標映射修正與單元測試。
