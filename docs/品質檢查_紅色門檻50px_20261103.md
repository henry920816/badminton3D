# 品質檢查紅色門檻改成 >50 px（2026-11-03）

這次只調整 **2D 位置修正的判斷門檻**，不改相機標定、不重建 3D，也不新增影像偵測。

## 新規則

- 3D 投影在畫面內，且有 2D 標註時，先計算兩點的像素距離。
- **≤20 px：無色正常**；**20～50 px：黃色**，保留原標註。
- **>50 px：若排除待修正相機後，仍有至少兩台幾何穩定的相機與原始 3D 相差 ≤20 px，且不在擊球前後各 5 幀、該點尚未修正，就顯示紅色**，提供移動至原始 3D 投影位置的候選。
- **>50 px 但未通過上述條件：紫色，留給人工檢視**，不可批次自動改動。
- **藍色視野外誤標優先判斷的規則不變**；達到安全條件可設為不可見。
- `50.0 px` 剛好等於門檻，仍是黃色；必須**大於 50 px** 才進入紅／紫分類。
- **人工或先前系統修正過的點不能再被批次覆蓋**。紅色只表示有幾何修正候選，不能當作影片已重新偵測成功。

## 修改檔案

- `backend/app/quality_review.py`：`AUTO_MOVE_PX` 由 100 改為 50，維持兩台其他視角、擊球保護、已有修正保護與視野外優先規則。
- `frontend/src/components/Quality2DPanel.jsx`：修正紅色批次按鈕的說明（100 → 50 px）。
- `backend/tests/test_quality_review.py`：補上 50 px 邊界、60 px 修正候選、支持不足、擊球保護、已修正保護，以及批次預覽／套用的測試。
- `docs/2D品質檢查_新版規則.md`、`docs/2D品質檢查_修正流程.dot`、`docs/2D品質檢查_修正流程圖_20261103.svg`、`.png`：更新文件與流程圖，避免顯示舊門檻。

## 安裝更新包

解壓縮後，在 PowerShell 執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\apply_update.ps1 -ProjectPath "D:\badminton3D"
```

`-ProjectPath` 是含 `backend` 和 `frontend` 的**專案根目錄**。安裝腳本會先備份被覆蓋的檔案。

這次有修改 Python 後端，**必須重新建置後端容器**：

```powershell
docker compose up -d db
docker compose up -d --build backend
```

前端若已在執行 Vite，通常會自動熱更新；若沒有顯示新提示，可重新啟動 `npm run dev` 並按 Ctrl+Shift+R。

無須清除資料庫，也**不要執行 `docker compose down -v`**。

## 測試限制

已有的單元測試及整合（SQLite）測試，無法取代真實 PostgreSQL、Docker 與影片的端對端驗證。請在實際影片中確認紅色候選是否可靠後再批次套用。
