# 專案架構與維護

這份專案主要做兩件事：同步觀看多視角影片與 3D 場景，以及檢查／修正羽球 2D 標註。先不要把「投影一致」誤認成「一定追到正確的球」。

## 目錄怎麼看

```text

  app/
    main.py                比賽資訊、Timeline、2D 查詢等共用入口
    dataset_routes.py      資料集上傳／查詢／刪除的 API
    dataset_upload.py      資料集上傳前的檢查、解析、匯入流程
    dataset_helpers.py     上傳欄位轉型及暫存路徑檢查
    dataset_cameras.py     相機內參、外參與投影參數解析
```

## 目前實際的判斷順序

1. 原始 3D 投影優先，但**品質判斷要有其他攝影機佐證**；顏色顯示使用原始投影的實際像素誤差。
2. 原始 3D 不足以判斷時，使用可信 2D 雙視角三角測量，回投檢查其他攝影機。
3. 還是不夠可靠，退回多視角幾何品質檢查。時間軌跡只提示可疑區段，**不會直接證明是隔壁場的球**。
4. 品質色塊：`≤15 px` 綠色、`15～30 px` 黃橘、`>30 px` 紅色；有 2D 標註但沒有原始 3D 投影時顯示紫色。

`ball2d_reference.py` 的「可信原始 3D 強制 OK」門檻現在與 15 px 綠色設定一致，修正了原始上傳版本中 **測試要求 15 px、程式卻寫 3 px** 的矛盾。顏色和後端判斷仍是兩種不同的資料：顏色顯示誤差，不代表有足夠獨立證據。

## 修改時先找哪裡

- **改品質顏色**：`frontend/src/utils/qualityProjectionColor.js`，不要在 `Quality2DPanel.jsx` 裡重複寫另一套門檻。
- **改誤標偵測**：先看 `ball2d_reference.py` 與 `triangulation.py`，需要時間資訊再看 `quality2d_temporal.py`。
- **改自動修復數學**：`repair_geometry.py`；**改儲存與復原**：`auto_repair.py`、`ball2d_corrections.py`。
- **改介面分割比例**：`frontend/src/hooks/usePanelLayout.js`；**改資料集切換**：`frontend/src/hooks/useMatchBootstrap.js`。
- **改影片疊圖**：`VideoPanel.jsx` 和 `utils/cameraProjection.js`。
- **改上傳檔案格式**：`dataset_upload.py`、`dataset_cameras.py`；**改 API**：`dataset_routes.py`。

## 執行與測試

```powershell
# 專案根目錄（先啟動 Docker Desktop）
docker compose up --build -d

cd frontend
npm ci
npm run dev
```

瀏覽器一般開 `http://localhost:5173`。如果只是修改前端程式，通常不需要重建後端；若改了 Python 服務，請重建 Docker 容器。

後端測試（需安裝 `backend/requirements.txt`）：

```powershell
cd backend
$env:DATABASE_URL = "sqlite:///./test.sqlite3"
python -m pytest -q
```

前端邏輯測試：

```powershell
cd frontend
node --test tests/*.test.mjs
npm run build
```

## 不要直接刪的東西

- `frontend/public/models/`：人體、球拍、羽球模型及貼圖；圖片、`.bin` 看起來很大，但畫面需要。
- `backend/app/reconstruction_gender.csv`：匯入重建資料用的對照表。
- `backend/app/trajectory3d_api.py`、`trajectory3d_core.py` 及資料表模型：雖然移除了前端 3D 修正頁面，舊版本、外部 API 或既有資料庫可能仍在使用。等確認沒有使用者依賴，再考慮移除。
- `backend/app/legacy_traj_repairs.py`：舊版 API／測試仍會呼叫。刪之前需要資料搬遷與相容版本規劃。

**自動修正的候選不等於真實影像球心。** 隔壁場誤標可能造成多台相機幾何一致，仍須影片和跨影格身份確認。修改時不要把所有小誤差點直接當真值，也不要在沒有復原機制時批次覆寫原始標註。
