# 品質檢查：區段審核與操作效率改善（2026-11-03）

## 這次修的問題

原本品質檢查把所有零碎異常畫成大量色塊，下方又把每一小段做成按鈕。
遇到漏標、少量跳點或一整段追蹤錯誤，很難知道要先看哪裡。
這次**沒有重新偵測羽球，也沒有調整 20/50/100 px 的修正門檻**。

## 修改內容

1. Rally 總覽預設改用「異常區段」顯示，而不是每幀碎片色塊。放大到 200 幀內仍可看原本逐幀色塊；取消「區段總覽」可隨時檢視完整逐幀顏色。
2. 同視角中間相隔最多 5 幀的異常會歸成同一待處理事件（最長 180 幀）。這**只是清單與畫面合併**，不會補標註、更不會將缺口自動修正。
3. 預設清單「優先處理」保留所有可自動修正影格，另顯示連續 3 個以上異常影格的事件。零星人工事件可切換「全部（含零星）」查看。
4. 可能漏標（3D 在畫面內但 2D 缺失）先隱藏於重點顯示。勾選「包含可能漏標」可恢復。此項不會刪除資料，也沒有將它自動判為正確。
5. 點擊事件：選相機、跳到第一個異常影格、縮放到整段上下文。可按 N 前往下一個待處理事件。
6. 每個可自動處理的事件有「修 N」按鈕，**只修該視角、該影格區間**；後端新增 `camera_indexes` 過濾，避免波及同時間其他相機。先顯示候選數量，使用者確認後才寫修正表。
7. 原本「🔵 視野外修正」、「🔴 位置修正」整個 Rally 批次功能不變。
8. 播放時移動目前影格線，不再每幀重畫整張品質格；後端擊球保護檢查改為二分搜尋。

## 安裝

推薦用上一份 11/03 品質檢查完整版作為基底，將更新包解壓縮後執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\apply_update.ps1 -ProjectPath "C:\你專案的資料夾"
```

也可把 `backend`、`frontend` 同名檔案覆蓋到原本專案根目錄。`apply_update.ps1` 會先把原始檔案備份到專案底下 `.quality_focus_backup_時間`，並在複製發生錯誤時恢復已覆蓋的檔案。

後端程式有更新，需重新建置：

```powershell
docker compose up -d db
docker compose up -d --build backend
```

前端停止後重啟 `npm run dev`，瀏覽器按 Ctrl+Shift+R。

## 重要限制

- 視野外、錯誤位置的自動修正仍依原本可信 3D 條件：至少 2 台其他視角支持、避開擊球前後 5 幀、保護已有修正。這次改進的是異常排程、介面展示和局部批次修復操作，不是影像辨識準確率。
- 「區段總覽」中的彩色長條是事件的**概略位置**，顏色代表事件主要類型；要核對每幀請點事件放大或取消「區段總覽」。
- 「優先處理」會暫時隱藏某些只有 1～2 幀的人工疑點，請定期切換「全部（含零星）」檢查。這些異常不會從資料或檢查結果中消失。
- 全域的紅藍批次修正照舊會預覽候選數量；仍須人工確認影片中羽球位置是否合理。
- 不能保證任何一段標註正確或必定是其他場的羽球；目前沒有重新偵測模型。
