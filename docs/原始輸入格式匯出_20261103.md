# Dataset 匯出：沿用原始上傳檔案

這版改掉「從資料庫反推原始檔」的匯出方式。資料集建立成功時，伺服器會在同一個 Docker 資料磁碟區另外保留上傳的原檔。匯出時只讀這些檔案，不再自己合成另一種 NPY、Mask、PTH 或縮減欄位的 CSV。

## 匯出內容

| 在 Export Dataset 勾選 | 匯出內容 |
| --- | --- |
| 相機參數 | 原始 `.npy`，檔名與二進位內容不變 |
| Rally 與擊球標註 | 原始 `RallySeg.csv`、`shot_annotated.csv`，保留原本所有欄位及順序 |
| 3D 球軌跡 | 原始 `.npy`，包括當初未被資料庫保留的數值 |
| 3D Mask | 原始 `.npy`，不以有效 3D 點重新產生 Mask |
| 2D 羽球位置 | 原始 `*_ball.csv` 的路徑、檔名與欄位；把 App 已儲存的 2D 修正寫入 `Visibility`／`X`／`Y` |
| 人體與球拍 | 原始 `.pth`、`.npz` 及 `gender.csv`，不再拿處理後的 NPZ 假裝成原始 PTH |

匯出的 ZIP 以六個資料類別當最上層目錄，各類別**底下的路徑與檔名依使用者上傳時的相對路徑原樣保存**。原檔若沒有修正則內容逐位元相同，2D 有修正的 CSV 才會重新寫入；Header 欄名、欄位順序、未修改的欄位、UTF-8 BOM 與換行種類會保留。2D 來源檔中沒有該 Frame 而使用者後來補了點，會在相同 CSV 補一列；原本沒有該 Rally／相機的 2D CSV，則新增一個符合匯入命名規則的 CSV。不存在對應 Rally 的孤立修正會阻擋匯出並顯示原因，不會默默漏掉。

**輸出格式相同，不代表所有資料都已更動。** 這次只把**2D 標註修正**合併到匯出檔；相機、3D、Mask、Rally、擊球與人體類別輸出的是當初上傳的**原始檔案快照**。如果你在 App 修改了 3D 軌跡或 Hit，這些改動**不會自動寫回原始 NPY 或原始 CSV**。這件事不能誤認為修正匯出已涵蓋所有資料類型。

## 舊資料集怎麼處理？

**過去匯入的舊資料集，不能從資料庫完全還原原始檔。** 舊版會在匯入後刪掉上傳暫存檔；資料庫中沒有原始 PTH、Mask 中的所有值、部分 CSV 欄位或原本的檔名。新版遇到沒有原檔的類別，會明確回傳錯誤，不再產生一個看起來格式一樣但其實資料有缺失的 ZIP。

處理方式有兩種：

1. **最推薦：** 用新版重新匯入一次原始 Dataset。從這次開始，所有上傳的原檔都會保留，之後可依類別匯出。
2. **保留既有資料庫：** 到 **Update Dataset**。2D CSV 使用上方「部分重傳」上傳原始 CSV，會同步更新那一段的原始 2D 資料，原有人工修正層保留；其他類別在下方「補回原始檔」選取資料夾或多個檔案，它們**只會被保存為匯出來源，不會重新計算、更新現有資料庫**。要完整匯出某類，需補齊該類全部原始檔。

## 重要的資料保護

- 原始檔保存在 `DATASET_ASSET_ROOT/match_<id>/original_uploads/`，Docker Compose 預設使用 `badminton_dataset_assets` Volume。請保留這個 Volume。
- 原始資料與 2D 修正層仍分開；匯出時才合併成可重新匯入的 2D CSV。
- 沒有修正的 NPY／PTH 不做格式轉換；避免改變 NumPy dtype／shape 或讓 PTH 消失。
- Export Dataset 只輸出所勾選類別，不額外塞入 `corrections.csv`、`export_info.json` 等非原始輸入格式的輔助檔案。
- 既有的「上一步／下一步」、藍色與紅色批次修正、品質檢查與 Timeline 不受這次修改影響。

## 安裝與測試

在專案根目錄套用更新包，重新建立後端：

```powershell
powershell -ExecutionPolicy Bypass -File ".\apply_update.ps1"
docker compose up -d --build --force-recreate backend
```

前端重新執行 `npm run dev`（已有啟動可停止後再開），瀏覽器用 `Ctrl+Shift+R` 重新整理。

程式檢查：後端以 SQLite 執行 159 項單元測試、前端 52 項 Node 測試通過；靜態檢查 38 個 JS／JSX 檔案與 75 條本地匯入路徑。**尚未實際操作使用者的 PostgreSQL、真實 Dataset 與瀏覽器進行端到端測試**。
