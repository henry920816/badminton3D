# 藍色人工檢視：單點與連續區段移除

基於 2026-11-03「藍色視野外批次修復」完整專案，保留前一版的品質檢查、Timeline、紅色 50 px 修正規則。

## 新規則

只要**原始 3D 投影明確位於相機影像範圍外**，且**該幀在所選 2D 資料來源有一筆可見標註**，品質格就顯示**藍色**。沒有距離邊界 50 px 緩衝，也不要求其他視角支持、不排除擊球附近、不排除先前已有可見位置修正的標註。相機參數無法使用、3D 缺失、影像尺寸未知時，不假裝知道投影在畫面外。

藍色代表**須人工檢視的視野外衝突**，不是自動修復候選。原本「🔵 視野外修正」整批按鈕已移除，舊的批次修復 API 不會自行改動藍色；紅色批次位置修正照舊。

## 品質格操作

- **單擊藍色格**：立即在修正層將該相機、該 frame 的 2D 標註設為 `visibility=0`，藍格從**修正後 2D**消失。
- **按住藍色格 0.6 秒（不拖動）**：從按住的格子向前後找同視角**逐格連續**的藍色，整段一次設為不可見。
- **拖動**：仍然可以在品質格移動影格。位移超過 7 px 會取消長按，不會誤刪。
- **復原上次 2D 修復**：復原最近一次單擊或長按；長按移除的整段一次復原。

所謂「連續」是每一幀都必須真的是藍色。若中間正常／紫色／沒有該 frame 資料，長按**不能跨過去刪除**。即使「區段總覽」把視覺上接近的事件合併，也不會以那個合併結果作為刪除範圍。

若目前檢視的是「原始 2D」，第一次人工移除會自動切換到「修正後 2D」以顯示結果。原始標註永不刪除。再次切回「原始 2D」仍可看到原有的藍格。

## 變更的檔案

- `backend/app/quality_review.py`：無附加限制的藍色判定，包含剛越過影像邊界的投影。
- `backend/app/review_repair_routes.py`：新增 `POST /matches/{match_id}/traj2d/review-hide`，同一請求處理單點或連續區段；後端重新驗證每幀是否仍為藍色，整批交易成功或整批 rollback。
- `frontend/src/components/Quality2DPanel.jsx`：單擊、0.6 秒長按、載入修正結果、復原操作；移除藍色自動批次按鈕。
- `frontend/src/utils/blueReviewSelection.js`：逐格連續藍色範圍工具。
- `frontend/src/utils/reviewQueue.js`：全覽須顯示零星單一藍格，否則點不到。
- `frontend/src/utils/qualityProjectionColor.js`、`frontend/src/api.js` 及測試：同步調整。

## 安裝

1. 將 ZIP 解壓縮到任意位置。
2. 在 PowerShell 用 `cd` 切換到含 `backend/`、`frontend/`、`docker-compose.yml` 的**原專案根目錄**。
3. 在該根目錄執行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File "<更新包路徑>\apply_update.ps1"
   docker compose up -d --build backend
   ```

4. 前端如已在執行 Vite，重新整理網頁（必要時 `Ctrl+Shift+R`）。

更新腳本會備份覆蓋前的檔案；不用刪除資料庫、不用重新匯入資料。

## 驗證與限制

- Python unittest 106 項通過（使用 SQLite 測試環境）。
- Node 前端 49 項邏輯測試通過；34 個 JS/JSX 檔案可被 TypeScript 轉譯解析，67 條相對匯入路徑有效。
- 沒有在使用者的 Windows + Docker/PostgreSQL + Vite 瀏覽器上做實際點擊與長按端對端測試。
- 未加入新的影片偵測模型，也不判定藍點究竟是隔壁場球還是球拍白點；藍色僅代表幾何上的視野外衝突，最終由使用者選擇是否移除。
