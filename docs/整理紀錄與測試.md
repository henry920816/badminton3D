# 這次整理做了什麼

以你上傳的 `bad.zip` 為基礎。目標是**減少檔案雜訊、讓功能邊界清楚，同時保留既有 API 和操作流程**；沒有重寫 3D 幾何、SMPL 或影片同步演算法。

## 已整理

- 上傳 ZIP 裡的 `frontend/node_modules/` 有 **12,630 個條目、約 288 MB 解壓大小**。已從交付專案移除，正式安裝使用 `npm ci`。
- 刪除未使用的舊前端頁面：`Projection2DPanel.jsx`、`Trajectory3DPanel.jsx`。介面仍只有 Timeline／品質檢查；影片內的 2D 人工修正保留。
- 刪除根目錄無使用者的 `jsdom` npm 專案及重複的舊版發布說明；操作說明集中到這兩份維護文件。相機查看腳本移到 `scripts/read_camera.py`。
- 前端所有來源檔案統一排版、整理多行靜態 CSS className，並檢查本地模組匯入是否都存在。
- `App.jsx` 拆出 `usePanelLayout.js`（面板拖曳）與 `useMatchBootstrap.js`（資料集切換與載入）；加上防止舊請求覆蓋新資料的檢查。
- `main.py` 拆出舊版修復路由與一般編輯路由；`dataset_upload.py` 拆出上傳 API、相機參數處理、共用資料轉換；`auto_repair.py` 拆出只做幾何運算的模組。
- 將 2D 時間軌跡繪圖的「相鄰影格才能連線」規則集中管理，保留你要求的缺幀斷線行為，並修正原 ZIP 內已過時的測試。
- 清除未使用的 `clsx`、`vis-data`、`vis-timeline` 直接依賴，並同步更新前端 lockfile。
- 修正原始專案後端測試要求 `15 px`、程式卻用 `3 px` 的不一致。這是有意的**行為修正**，其他拆檔／排版原則上不改演算法。

## 保留的功能

資料集上傳／刪除、影片同步、相機切換、SMPL 人體與球拍、Timeline 距離／速度、2D 標註編輯、品質檢查色塊、原始 3D 投影、多視角幾何檢查、自動修復預覽與復原、品質檢查的 XY／XYZ 對照曲線，以及既有的 3D API。

## 測試範圍與未驗證項目

- 後端 SQLite 單元／API 測試：**91 項通過**。
- 前端 Node.js 純邏輯測試：**44 項通過**。
- Python 編譯檢查與 **32 個前端 JS／JSX 檔案**語法檢查通過。
- 前端 **65 個相對 import** 均存在；前後版 **36 個 HTTP 路由簽名相同**。

**尚未跑過你的真實影片、PostgreSQL、Docker 容器整合、正式 Vite build。** 目前測試環境缺少 Linux 版 Rollup／esbuild 執行檔（上傳的 `node_modules` 是 Windows 版本），因此不能聲稱瀏覽器全流程已驗證。解壓後在你的 Windows 電腦執行 `npm ci && npm run build` 才能補上這部分。

`dataset_upload.py`、`VideoPanel.jsx`、`Scene3D.jsx` 和 `Quality2DPanel.jsx` 仍然偏大；內部 UI 和演算法互相牽連。這次先按可靠邊界拆開功能，保留原始資料流程，不做未測試的整體重寫。若繼續拆，先補真實資料集的整合測試，再調整影片同步與上傳交易流程。
