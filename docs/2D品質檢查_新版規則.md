# 品質檢查：藍色與紫色判斷更新（2026-11-03）

本次延續「雙擊移除單幀、長按 0.6 秒移除連續藍色」以及共用的 2D 上一步／下一步。只改品質分類與人工移除前的後端驗證，不改原始 2D 標註。

## 藍色

優先判斷，同一格有可見 2D 時：

- **沒有可用的 3D 投影**：藍色。例：當幀沒有 3D、相機投影參數錯誤或計算無法得到投影座標。這只代表缺乏參考，不保證 2D 是錯的；必須由人工決定要不要移除。
- **有投影、但投影在影像外**：當投影座標與 2D 的距離 **≥ 50px** 才是藍色。
- **有投影且相差 < 50px**：不標藍；≤20px 為正常，20～<50px 為黃色。這種情況可能只是邊界與投影誤差，不應一概刪除。
- **投影在影像內**：不走藍色，照以下位置誤差分類。
- **沒有可見 2D**：不標藍。

畫面尺寸未知、但仍算得出投影 XY，和「完全沒有投影 XY」不同，不能混為藍色。

雙擊藍格將該視角該幀設為不可見；長按只對真正逐幀連續的藍格操作。後端也會重新檢查 50px 條件，避免前端資料過期時誤刪。所有刪除都是寫入修正層，原始標註不變，可用共用的上一步／下一步復原。

## 減少紫色

- 2D 和原始 3D 相差 **50～100px**：如果不符合紅色修正條件，改顯示**黃色提醒**，不再預設丟到紫色逐幀檢查。
- 相差 **>100px**，但在擊球保護區內，或缺少其他兩台可信視角：維持**紫色人工檢視**，避免錯誤自動覆蓋。
- 2D 已經有修正紀錄：保留既有修正，當投影仍不一致時不再反覆顯示紫色；細節中的誤差數字仍保留。
- 投影座標存在但相機影像尺寸不明：50～100px 僅黃色；>100px 需要人工檢視，不使用這類相機當作 3D 支持證據。
- 原始 3D 在畫面內但沒有 2D：保留「可能漏標」，仍可用「包含可能漏標」開關檢查，預設不顯示。

紅色不變：一般非擊球區，至少兩台其他可信視角支持原始 3D，且該格偏差 **>50px**，才有可自動套用的投影修正候選。沒有 3D、視野外的藍色都不自動刪除。

## 安裝

在專案根目錄（含 `frontend` 與 `backend`）執行解壓縮更新包中的 `apply_update.ps1`。再執行：

```powershell
docker compose up -d --build backend
```

前端若已在運行請重新整理。請使用「修正後 2D」來源檢視刪除效果；切回「原始 2D」會看到未修改的原始標註。

## 藍色一鍵消除（11/03）

品質檢查上方有「🔵 一鍵消除藍色 (N)」，按一次就將**目前 Rally、所有相機**符合藍色條件的可見 2D 標註設為不可見。
不用確認視窗；處理範圍不會超過目前 Rally。
同一批消除只算一次「上一步」操作，「下一步」可重做。原始 2D 不更動。
要只處理部分藍色，仍可以雙擊單幀，或長按 0.6 秒消除同一相機的連續藍色段。
這裡的藍色依目前品質規則：無有效 3D 投影但有可見 2D；或投影在畫面外且與 2D 距離至少 50px。
